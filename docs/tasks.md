## Критерий завершения

- У каждого из пяти разделов своя карточка и свой экран деталей.
- Статусы звучат по-человечески.
- У сериалов, аниме, книг и игр есть прогресс.
- «Продолжить» работает для сериалов и аниме.
- В каждом разделе есть свои фильтры и создание нужного типа.
- Публичная и своя карточки не смешивают приватное и публичное.
- Новые типы контента не добавлялись.

### B125 · Стабилизация веба перед desktop

Не «идеальный веб», а предсказуемое состояние:

- закрыть критические UX-баги;
- проверить мобильный вид;
- зафиксировать модель записи;
- зафиксировать публичный и приватный API;
- проверить бэкапы и восстановление;
- не добавлять новые типы контента;
- не делать больших редизайнов.

Критерий выхода:

```text
пять разделов работают
коллекции работают
приватность работает
критических багов нет
API стабилен
```

### B126 · Sync API и протокол

До десктопа нужен контракт, а не Tauri-оболочка:

- `sync/push`;
- `sync/pull`;
- `sync/status`;
- идемпотентность операций;
- надгробия и курсоры;
- конфликтные копии;
- тесты на повторный push и pull;
- версия протокола.

Критерий выхода: два клиента могут создать, изменить и удалить запись,
выйти в офлайн, вернуться и синхронизироваться без дублей.

### B127 · Desktop MVP на Tauri

Минимальный клиент, а не копия сайта:

- вход;
- список записей;
- карточка;
- создание и редактирование;
- локальная SQLite;
- офлайн-очередь;
- кнопка «Синхронизировать»;
- индикатор состояния.

Не входит в MVP:

- комментарии;
- рекомендации;
- админка;
- сложные коллекции;
- синхронизация медиа.

Критерий выхода: можно вести библиотеку офлайн и синхронизировать её с сервером.

### B128 · Desktop: медиа и полировка

После работающего MVP:

- кэш обложек;
- офлайн-просмотр изображений;
- синхронизация вложений;
- автозапуск;
- автообновление;
- подпись сборок;
- Windows и Linux;
- восстановление после конфликтов.

### B129 · Новые типы контента после desktop

Только после B127:

- заметки;
- изображения;
- видео;
- музыка;
- импорт библиотеки;
- судьба скрытых `image`/`other`.

Это продуктовое решение, а не автоматическое продолжение. До него нужно
понять, какие типы действительно нужны и как они синхронизируются.

### Перед B126 нужно решить

- Windows и Linux сразу или сначала Linux?
- Сервер — источник истины или клиент может жить автономно?
- Синхронизировать медиа сразу или только метаданные?
- Нужно ли шифрование локальной базы?
- Что делать при входе в офлайне?
- Нужна ли общая библиотека для нескольких устройств?

2. При старте — строка в «Сейчас», статус `[~]`, дата и первая заметка.

   и перенести подробности в `done.md`.
4. Старые комментарии не переписывать: это история.
