2. **T169 → T170 → T171** — производительность, безопасность, эксплуатация.

5. **T179 → T180** — только после зелёных P0/P1; desktop — по команде.

### Definition of Done стабилизации

- нет открытых P0;
- критические сценарии покрыты E2E;
- CI зелёный с чистой машины;
- API p95 в бюджете, тяжёлые запросы имеют индексы;
- restore из backup проверен;
- offline-сценарии не ломают локальную библиотеку;
- клавиатурная навигация и контраст проверены;
- документация и версия совпадают с production.

### T183 · Решение по Windows-подписи и auto-update

**Приоритет:** P1. **Оценка:** 0.5 d.

Нужно не «сделать когда-нибудь», а зафиксировать решение:

- Windows остаётся unsigned или покупается сертификат;
- auto-update не нужен, нужен только manual check, или включаем
  подписанные обновления;
- кто хранит приватный ключ updater и что будет при его потере.

**Готово, когда:**

- решение записано в `docs/release-desktop.md`;
- T179 получает честный статус `[x]` или остаётся `[~]` с конкретным блокером;
- T185 либо создаётся как работа, либо помечается отменённой.

**Решение T183:** Windows остаётся unsigned. Auto-update включаем: пользователь
нажимает «Обновить», приложение скачивает подписанный артефакт и применяет его.
SmartScreen для Windows остаётся отдельным известным ограничением.

### T184 · Автопроверка опубликованного релиза

**Готово, когда:** `bash scripts/verify-release.sh vX.Y.Z` падает на старом

### T188 · Singleton notification stream

**Приоритет:** P1. **Оценка:** 1 d.

Сейчас SSE открывает колокольчик, а страница/лента слушают window-событие.
Из-за порядка подписки возможна потеря первого события.

Нужен один общий stream:

- одно EventSource на приложение;
- поздние подписчики получают последнее событие;
- reconnect и fallback polling остаются;
- у страницы уведомлений нет собственной гонки.

**Готово, когда:** тест «событие пришло до монтирования страницы» проходит
стабильно.
