# Данные, backup и восстановление

## Где хранятся данные

Desktop хранит библиотеку локально:

| Платформа | Путь по умолчанию |
|---|---|
| Linux | `~/.local/share/net.jey.desktop` |
| Windows | `%APPDATA%\net.jey.desktop` |

Папку можно изменить в **Настройки → Локальные данные → Выбрать папку**.
После выбора приложение нужно перезапустить.

В папке:

```text
jey.db          локальная SQLite-библиотека
jey.db-wal      журнал SQLite
media/          кэш обложек
access.json     локальный доступ к библиотеке
session.json    серверная сессия
backups/        резервные копии
exports/        JSON-экспорт
```

`access.json` и `session.json` имеют права `600`. Папка данных — `700`,
`jey.db` и WAL/SHM — `600`.

## Backup

### Вариант 1 — скопировать папку

1. Закрой jey.net.
2. Скопируй всю папку данных на другой диск.
3. Для восстановления верни папку на место.

Это самый полный backup: база, обложки, доступ и настройки.

### Вариант 2 — встроенный backup

Перед миграцией SQLite приложение автоматически создаёт:

```text
backups/pre-migration-v<версия>-<timestamp>/
```

Внутри — `jey.db` и `manifest.json`.

Команда `local_backup` также умеет создавать консистентную копию базы и
`media/`; результат складывается в `backups/<timestamp>/`.

### Вариант 3 — JSON-экспорт

**Настройки → Экспорт JSON** создаёт читаемый файл в `exports/`.
Он подходит для переноса записей, но не заменяет полный backup:
сессия, настройки и кэш обложек в JSON не входят.

## Restore

1. Закрой jey.net.
2. Сделай копию текущей папки данных.
3. Замени `jey.db` и `media/` из backup.
4. Удали `jey.db-wal` и `jey.db-shm`, если они остались от старого файла.
5. Запусти приложение.

Если восстанавливаешь всю папку — верни также `access.json` и `session.json`,
иначе потребуется повторный вход.

Не запускай две копии приложения на одной и той же папке данных: SQLite
блокирует запись, второе приложение получит ошибку занятости.

## Если сервер недоступен

Локальная библиотека продолжает работать:

- открывать и редактировать записи;
- смотреть обложки из кэша;
- создавать коллекции и комментарии;
- делать JSON-экспорт и backup.

Sync, публикация, чужие профили и комментарии требуют сервера. Изменения
остаются в `outbox` и уйдут при следующем sync.

Первый вход на новом устройстве требует сервера. Истёкшая сессия не удаляет
локальный доступ; после явного «Выйти» потребуется войти снова.

## Конфликты

### Записи

Конфликты записей сохраняются на сервере и разрешаются через API
`/api/v1/sync/conflicts`; отдельного экрана для них пока нет.
Подробности — [sync.md](sync.md).

### Коллекции и комментарии

Открой **Настройки → Конфликты синхронизации**. Там видны обе версии и
кнопки «Оставить серверную» / «Оставить входящую».

### Профиль и лайки

Работают по правилу last-write-wins: последняя запись побеждает.
Это осознанное ограничение 0.3.x.
