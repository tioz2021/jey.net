# Error handling

Правило: `catch` не должен быть пустым. Допустимы два варианта:

1. ошибка обрабатывается и меняет состояние/показывает сообщение;
2. ошибка осознанно best-effort, но рядом есть комментарий, объясняющий,
   почему её можно не показывать.

Критичные потери — черновик формы, профиль пользователя, bridge-роутинг —
дополнительно сообщаются через `reportClientError(scope, error)`:
`console.warn` плюс событие `jey:client-error`.

Проверка:

```bash
bash scripts/check-silent-catches.sh
```

Она входит в `scripts/check.sh` и падает на `catch {}` без кода и без
объясняющего комментария.
