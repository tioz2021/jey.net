# Чат: threat model

Версия: MVP 1:1. Документ относится к T133.

## Активы

- тело сообщений и метаданные (кто, кому, когда);
- список диалогов и непрочитанные;
- блокировки и настройки «кто может писать»;
- сессии и access/session cookies;
- локальный кеш desktop;
- резервные копии БД и логи.

## Границы доверия

```text
браузер / desktop
      │ HTTPS, session cookie
      ▼
Rust API (axum)
      │ SQL, параметризованные запросы
      ▼
PostgreSQL
      │
      ├── SSE-подписчики
      └── резервные копии
```

- Клиент не является доверенным.
- Desktop-кеш находится на устройстве пользователя.
- Оператор сервера и БД технически может читать сообщения: E2E в MVP нет.
- В MVP нет admin-API для чтения чужих сообщений.

## Акторы

- обычный участник диалога;
- пользователь, который пытается читать чужой диалог;
- заблокированный пользователь;
- спамер / abuser;
- неаутентифицированный атакующий;
- оператор сервера;
- злоумышленник с доступом к устройству или локальному кешу.

## Угрозы и контрмеры

| Угроза | Контрмера |
|---|---|
| IDOR: чтение чужого thread/message по id | Каждый запрос проверяет membership в `chat_members`; для не-участника — 404, не 403 |
| Подмена отправителя | `sender_id` всегда берётся из сессии, не из body |
| Отправка в чужой диалог | Проверка членства и блокировок в одной транзакции |
| Создание диалога с заблокированным | Проверка block в обе стороны |
| Обход настройки «кто может писать» | Проверка policy при создании и при каждом сообщении |
| Спам и флуд | Rate limit на сообщения и новые диалоги, лимит длины |
| Перебор пользователей | Только публичные профили, единый 404, rate limit |
| XSS через сообщение | React выводит текст как text node; HTML не интерпретируется |
| SQL injection | Только bind-параметры, без конкатенации SQL |
| CSRF | Существующая проверка Origin/Referer для state-changing запросов |
| Кража SSE-событий | SSE требует сессию; события фильтруются по membership; без тела в URL |
| Утечка через title/уведомления | В title только счётчик, без имени и текста; без push/email в MVP |
| Повторная отправка при retry | `unique(thread_id, client_id)`; повтор возвращает существующее сообщение |
| Гонка при создании двух direct-диалогов | `direct_key` canonical pair + unique constraint |
| Подделка `client_id` | Уникальность в рамках thread; не влияет на автора |
| Огромные/битые сообщения | 1..4000 символов, control chars кроме `\n`/`\t` отклоняются |
| Утечка в логах | Тело сообщений не логируется; только id/count/error code |
| Доступ оператора к БД/бэкапам | Явно документировано; E2E — T150, не MVP |
| Локальный кеш desktop | Каталог 700, файлы 600; кеш очищается при выходе/удалении |
| Подмена offline-очереди | Очередь принадлежит текущему local user; сервер проверяет автора |
| Удаление аккаунта | Каскадное удаление membership; политика сообщений фиксируется в T134 |
| Блокировка после начала диалога | Новые сообщения запрещены; диалог становится read-only |

## Инварианты авторизации

1. Пользователь видит только те threads, где он есть в `chat_members`.
2. Пользователь может отправить сообщение только в thread, где он участник.
3. Заблокированный пользователь не может создать новый thread или отправить сообщение.
4. Настройка `message_policy` проверяется до создания/отправки.
5. `sender_id` не принимается из клиента.
6. Любая ошибка доступа к чужому объекту — `404 not_found`.
7. SSE-сообщения отправляются только участникам конкретного thread.

## Решения MVP

- **Кто может писать:** по умолчанию все активные пользователи; настройка
  `all / following / nobody` (T142).
- **Удаление сообщений:** в MVP сообщения не редактируются и не удаляются
  по одному. Можно скрыть диалог у себя (`chat_members.hidden_at`).
- **Retention:** история хранится до удаления аккаунта; удаление аккаунта
  удаляет membership, сообщения обрабатываются по политике T134.
- **Уведомления:** только badge/title на сайте; push/email — после MVP.
- **Шифрование:** TLS в транспорте, без E2E; это явно написано в UI.
- **Блокировка:** старый диалог остаётся read-only, новые сообщения запрещены.
