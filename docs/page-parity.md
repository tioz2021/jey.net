# Постраничная SPA-миграция без регрессий

Статус: T127, 7 ноября 2026.

## Главное правило

Старый маршрут не переключается и не удаляется, пока новый экран не достиг
полного паритета по функциям. Никаких заглушек на месте рабочей страницы.

## Схема

1. Инвентаризация функций старой страницы.
2. Shared-компонент в SPA.
3. Отдельный shadow-маршрут `/spa/...`.
4. Функциональная и визуальная проверка.
5. Только затем переключение основного маршрута.
6. Старая страница удаляется отдельным коммитом.

Пока паритет не достигнут:

```text
/items/[id]       — старая рабочая страница
/spa/items/[id]   — новая SPA-версия
```

## Чек-лист страницы

- все данные;
- все действия;
- loading / empty / error / unauthorized;
- навигация и deep links;
- мобильная и десктопная вёрстка;
- клавиатура и доступность;
- поведение без сервера для desktop;
- отсутствие Next-зависимостей в shared-компоненте.

## Desktop заморожен

До завершения веб-миграции **не трогаем desktop**:

- не меняем `apps/desktop`;
- не меняем `crates/desktop`;
- не меняем Tauri-конфиг;
- не запускаем `desktop-build.sh`, `desktop-run.sh` и `cargo tauri`;
- не тратим время на медленный rebuild после каждой задачи.

Desktop подключается **одной отдельной задачей** после того, как веб-SPA
достигнет паритета:

```text
T127.9 · Подключить готовую Web SPA к Tauri
```

До этого все изменения идут только в:

```text
apps/web/        новая Vite SPA
frontend/        общие компоненты
crates/api/      сервер
```

```bash

DEPLOY_HOST=129.121.149.16 bash scripts/deploy.sh
```

```text

```

UUID можно взять из `/api/v1/items?limit=5` или из локальной базы desktop.
