# Тесты чата (T145)

## API

```bash
set -a && . ./.env && set +a
cd crates/api
cargo test --test chat_schema --test chat_threads --test chat_messages \
  --test chat_privacy --test chat_events --test chat_load
```

Покрыто:

- схема, уникальный direct key, FK и идемпотентность `client_id`;
- создание, список, скрытие и приватность диалогов;
- отправка, пагинация, read, блокировка, policy;
- mute;
- жалоба на сообщение и очередь модерации;
- 40 сообщений, повтор `client_id`, отсутствие пересечения страниц;
- доставка события между двумя `ChatEvents` через PostgreSQL `LISTEN/NOTIFY`.

## Desktop / offline

```bash
cargo test -p jey-desktop --lib
cargo test -p jey-desktop --test chat_offline
```

Покрыто:

- кеш диалога и сообщений;
- очередь офлайн-сообщения с `client_id`;
- сохранение кеша и outbox после перезапуска;
- замена pending-сообщения серверным при reconnect;
- очистка outbox после успешной отправки.

## Web E2E (ручной прогон)

Проверено в браузере:

1. Войти двумя тестовыми аккаунтами.
2. Открыть `/messages` — список, unread, бейдж в сайдбаре.
3. Открыть диалог — история, отправка, собственные/чужие бабблы.
4. Отправить два сообщения подряд — нет дублей.
5. Открыть `/notifications` — клик по одному уведомлению снимает только его.
6. Включить mute — диалог исключается из общего бейджа.
7. Заблокировать собеседника — отправка запрещена, история читается.
8. Открыть жалобу на чужое сообщение — она появляется в `/admin/reports`.

## Ограничения

- E2E-браузер не входит в `scripts/check.sh` (нет отдельного browser harness);
- нагрузочный тест проверяет 40 сообщений, не p95 latency;
- offline desktop проверяется на уровне store и Tauri-команд, без отключения сети
  в запущенном WebView.
