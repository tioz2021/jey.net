# Спецификация продукта

Статус: черновик для MVP. Документ описывает **что** мы делаем; **как** —
в [architecture.md](architecture.md) и [protocol.md](protocol.md).

## 1. Идея

Портал, в котором человек ведёт личный каталог всего, что он посмотрел,
прочитал и сохранил: фильмы, книги, картинки, ссылки. В отличие от десятка
разрозненных сервисов, здесь всё в одном месте, с единой системой оценок,
заметок, тегов и статистики.

Ключевая ценность — **свои данные и своя систематизация**, а не лента
рекомендаций. Пользователь приходит, чтобы быстро записать «посмотрел,
8/10, понравилось» и позже найти это.

## 2. Для кого

| Роль | Что делает |
|---|---|
| Гость | Смотрит лендинг, регистрируется, входит |
| Пользователь | Ведёт свой каталог: добавляет, оценивает, тегирует, ищет, смотрит статистику |
| Владелец портала | Следит за работоспособностью, модерирует публичный контент |

Социальные функции (друзья, лента, комментарии) — не в MVP, см. раздел 8.

## 3. Типы записей

Каждая запись принадлежит пользователю и имеет один из типов:

| Тип | Обязательные поля | Дополнительные |
|---|---|---|
| `movie` | название | год, режиссёр, длительность, оценка, статус |
| `book` | название | автор, год, страницы, оценка, статус |
| `image` | изображение или ссылка | источник, автор, теги |
| `other` | название | ссылка, заметка |

Общие для всех: `title`, `status`, `rating` (1–10), `review` (текст),
`tags`, `created_at`, `updated_at`.

Статусы (одинаковый набор для всех типов):

- `planned` — «хочу посмотреть / прочитать / сохранить»
- `in_progress` — «смотрю / читаю»
- `done` — «посмотрел / прочитал / сохранил»
- `dropped` — «бросил»

## 4. Функции MVP

### 4.1 Аккаунты

- Регистрация по email и паролю.
- Вход, выход, «запомнить меня» (длительная сессия).
- Смена пароля, сброс пароля по email.
- Подтверждение email.
- Профиль: отображаемое имя, настройки приватности.
- Удаление аккаунта с удалением всех данных.

### 4.2 Записи

- Создание, просмотр, редактирование, удаление.
- Мягкое удаление с корзиной и восстановлением.
- Списки с сортировкой (дата добавления, дата изменения, оценка, название, год).
- Фильтры: тип, статус, тег, год, оценка.
- Поиск по названию, автору и тексту заметки.
- Теги: создание на лету, привязка, фильтрация.

### 4.3 Медиа

- Загрузка изображения для записи (обложка/постер) или для записи типа `image`.
- Автоматический ресайз и превью.
- Лимиты: размер файла, количество на пользователя.
- Удаление неиспользуемых файлов.

### 4.4 Статистика

- Всего записей по типам.
- Средняя оценка.
- Распределение по годам и статусам.
- «Сколько посмотрел/прочитал за месяц/год».

### 4.5 Данные

- Экспорт всех данных в JSON (и CSV для записей).
- Импорт из JSON-экспорта (идемпотентно, с отчётом о конфликтах).

### 4.6 Приватность

- По умолчанию всё приватно.
- Публичный профиль — опционально, с выбором, что показывать.
- Ссылка на профиль только по явному включению.

## 5. Пользовательские истории (MVP)

1. Как новый пользователь, я регистрируюсь по email и сразу попадаю в пустой каталог.
2. Как пользователь, я добавляю фильм за 15 секунд: название, оценка, статус.
3. Как пользователь, я вижу всё, что смотрел, и могу отфильтровать по оценке.
4. Как пользователь, я нахожу запись по части названия.
5. Как пользователь, я загружаю постер и вижу его в списке.
6. Как пользователь, я вижу, что посмотрел 27 фильмов и 6 книг за год.
7. Как пользователь, я ошибочно удалил запись и восстанавливаю её из корзины.
8. Как пользователь, я выгружаю все свои данные в JSON.
9. Как пользователь, я меняю пароль и все прочие сессии завершаются.
10. Как пользователь, я удаляю аккаунт и данные исчезают безвозвратно.

## 6. Нефункциональные требования

| Свойство | Требование |
|---|---|
| Время ответа API | p95 < 300 мс на обычных операциях |
| Время загрузки страницы | < 2,5 с на 4G, LCP |
| Доступность | 99,5% в месяц (допустимо ~3,5 ч простоя) |
| Безопасность | Пароли только argon2id; сессии в HttpOnly cookie; защита от CSRF и перебора |
| Приватность | Данные не отдаются другим пользователям без явного разрешения |
| Резервное копирование | Ежедневный дамп БД, проверка восстановления раз в месяц |
| Мобильность | Интерфейс работает на экране от 360 px |
| Доступность (a11y) | Навигация с клавиатуры, контраст не ниже AA |

## 7. Ограничения

- Один экземпляр приложения на VPS 1–2 vCPU / 2 ГБ RAM на старте.
- До 10 000 записей на пользователя без деградации интерфейса.
- Объём загруженных файлов — не более 200 МБ на пользователя (настраивается).
- Язык интерфейса MVP — русский; строки выносятся отдельно, чтобы позже
  добавить украинский и английский.

## 8. Вне рамок MVP

Осознанно отложено, чтобы не раздувать первый релиз:

- друзья, подписки, лента активности, комментарии;
- рекомендации и совместная фильтрация;
- интеграции с внешними API (TMDB, Open Library) для автозаполнения;
- мобильные приложения;
- совместные списки и публичные коллекции;
- монетизация, платные тарифы;
- полнотекстовый поиск на собственном индексе.

Каждый пункт может стать отдельной задачей в бэклоге после 0.1.0.

## 9. Критерии приёмки MVP

MVP считается готовым, когда:

1. Новый пользователь может зарегистрироваться, подтвердить email, войти.
2. Он может создать, отредактировать, удалить и восстановить запись каждого типа.
3. Работают фильтры, сортировка, поиск и теги.
4. Загружается и отображается изображение.
5. Считается статистика.
6. Данные экспортируются в JSON.
7. Всё работает на телефоне.
8. Приложение развёрнуто на VPS с HTTPS, бэкапами и мониторингом.
9. Прогон `scripts/check.sh` и сквозной smoke-тест проходят.

## 10. Метрики успеха

Не про бизнес, а про качество:

- регистрация до первой записи — меньше 1 минуты;
- добавление записи — меньше 20 секунд;
- ни одной потери данных за время беты;
- отсутствие ошибок 5xx в логах, кроме запланированных работ.
