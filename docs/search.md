# Поиск: единый контракт

Статус: T124, 7 ноября 2026.

Один и тот же контракт используют сервер и desktop:

- `crates/core/src/search.rs` — нормализация, скоринг и сортировка;
- сервер получает кандидатов SQL, затем сортирует их общим `rank_items`;
- desktop ищет по локальным `Item` тем же `rank_items`.

## Поля

- название записи;
- локализованные названия из `details.translations`;
- автор/режиссёр (`subtitle`);
- рецензия;
- метаданные: оригинальное название, описание, жанры, актёры, авторы.

## Нормализация

- нижний регистр;
- `ё → е`;
- trim и схлопывание пробелов;
- сравнение по вхождению.

## Приоритеты

| Совпадение | Баллы |
|---|---:|
| точное название или перевод | 1000 |
| название начинается с запроса | 800 |
| название содержит запрос | 600 |
| автор/режиссёр | 400 |
| рецензия | 300 |
| метаданные | 100 |

При равном счёте выше более свежая запись, затем название.

## Что умеет

- «Троя» находит запись с `title = Troy` и переводом `Троя`;
- регистр и `ё/е` не важны;
- результаты одинаково ранжируются в вебе и desktop.

## Ограничения

Нечёткий поиск и semantic fallback пока не входят в общий контракт.
Их можно добавить в `jey_core::search` и автоматически получить в обоих
клиентах.
